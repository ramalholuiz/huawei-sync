# Research: APIs, constraints, and references

Last reviewed: 2026-07-14.

## Android Health Connect

Official references to verify during implementation:

- Health Connect Jetpack release page: https://developer.android.com/jetpack/androidx/releases/health-connect
- Health Connect workout guidance: https://developer.android.com/health-and-fitness/health-connect/experiences/workouts
- Health Connect write data guidance: https://developer.android.com/health-and-fitness/health-connect/write-data
- `HealthConnectClient` API reference: https://developer.android.com/reference/androidx/health/connect/client/HealthConnectClient

Confirmed planning facts from official Android documentation:

- The Jetpack artifact is `androidx.health.connect:connect-client`.
- The stable Health Connect Jetpack release shown on the official release page at review time is `1.1.0`; the latest alpha shown is `1.2.0-alpha04`.
- `HealthConnectClient` exposes availability statuses including `SDK_AVAILABLE`, `SDK_UNAVAILABLE`, and `SDK_UNAVAILABLE_PROVIDER_UPDATE_REQUIRED`.
- Health Connect workout guidance recommends setting `metadata.clientRecordId` to prevent duplicates during sync retries.
- Health Connect write-data guidance documents `clientRecordId` and `clientRecordVersion` as synchronization metadata.

Implementation implication:

- Gate 1 should use the stable `androidx.health.connect:connect-client:1.1.0` unless a specific API requires a newer officially documented version.
- The synthetic workout must be an `ExerciseSessionRecord` using a deterministic `metadata.clientRecordId` and a monotonic `clientRecordVersion` strategy.
- The app must read back its own records by client record ID and/or ledger state to prove idempotency.

## Huawei Health Service Kit / Health Kit

Official references to verify during implementation:

- Health Service Kit guide, open data overview: https://developer.huawei.com/consumer/pt/doc/HMSCore-Guides/data_description-0000001467889369
- Enabling Health Service Kit in Huawei: https://developer.huawei.com/consumer/pt/doc/HMSCore-Guides/managing-fitness-and-health-data-0000001240326527
- Activity records API reference: https://developer.huawei.com/consumer/en/doc/HMSCore-References/activityrecords_list-0000001050114862

Confirmed planning facts from official Huawei documentation search results and pages:

- Huawei documents Health Service Kit / Health Kit capabilities for accessing health and fitness data generated by Huawei smart wearables and Huawei Health.
- Huawei documentation includes activity record APIs and open data descriptions.
- The project must use Huawei's official developer flow: Huawei Developer account, AppGallery Connect configuration, package name, signing certificate, service enablement, user authorization, and official SDK/API integration.

Open questions to resolve in Gate 2:

- Exact current Gradle dependency coordinates and versions for Android device-side Huawei Health Service Kit.
- Exact permission/scope names required for reading workout/activity records.
- Whether Open Testing or restricted release is required before the owner's app can access the needed data.
- Whether Huawei returns all needed workout fields from Huawei Watch Fit 5 Pro via Huawei Health.
- Whether region/account restrictions apply.

## GymRats

No direct GymRats integration is in MVP scope. The vertical slice treats GymRats as a consumer of Health Connect.

Required manual validation:

- Install GymRats on the owner's device.
- Grant GymRats Health Connect permissions required to read exercise sessions.
- Write the synthetic Gate 1 workout.
- Confirm whether GymRats imports or displays workouts written by this app.
- Repeat with a real Huawei workout in Gate 4.

Blocking risk:

- If GymRats does not read third-party `ExerciseSessionRecord` data from Health Connect, the project cannot satisfy the goal without changing scope, because direct GymRats integration is explicitly outside MVP.

## Strava optional fallback

Strava is optional and must not be implemented before Gate 1 and Gate 2 pass. It should remain out of the initial vertical slice unless Huawei access is blocked later and the plan is explicitly revised.

Rules:

- Use official Strava APIs only.
- Keep Strava DTOs outside the domain model.
- Use deterministic source IDs and a cross-source deduplication strategy so the same Huawei-origin workout is not imported from both Huawei and Strava.
